# VulcanIQ Participant & Terms Release — Admin Test Guide

Use only the approved controlled test booking. Preview Pages uses Preview D1 but the shared Production Supabase project, so participant, invitation, Terms, and acceptance writes are real Production-backend writes. Do not publish test Terms or enable Cron without the separate approvals recorded in the release plan.

Record the Preview URL, deployment SHA, tester, device, and approximate test time before starting.

## A. Booking participant details

- [ ] Open an accepted controlled booking.
- [ ] Verify the organizer appears as **Adult / Organizer**.
- [ ] Add an additional adult.
- [ ] Add a minor and assign an active adult guardian from the same booking.
- [ ] Edit a participant and refresh the page.
- [ ] Verify removing or demoting a guardian with an active dependent minor is rejected.
- [ ] Verify an invalid cross-booking guardian is rejected.
- [ ] Create a composition mismatch and verify the warning appears.
- [ ] Verify participant edits do not silently rewrite the booking's adult/child totals.

## B. Organizer Terms

- [ ] Verify applicable Terms appear only after an approved version is published.
- [ ] Verify the organizer can accept only for themselves.
- [ ] Accept once and verify the organizer status changes to **Accepted**.
- [ ] Refresh and verify the evidence remains.
- [ ] Repeat the submission and verify no duplicate evidence is created.

## C. Additional adult invitation

- [ ] Enter an email address controlled by the test participant.
- [ ] Select **Send invitation**.
- [ ] Verify the organizer sees only a masked destination and no URL/token/copy/share control.
- [ ] Verify Admin has no bearer credential or full invitation destination.
- [ ] Check the participant mailbox and open the invitation.
- [ ] Review and accept the exact displayed Terms.
- [ ] Return to the owned booking and verify the adult is **Accepted**.
- [ ] Verify actor and target are the same adult with representation `self` in authorized evidence review.
- [ ] Verify the email was not added to booking notification preferences.
- [ ] Try the consumed URL again and verify it cannot create another evidence row.

## D. Minor — organizer guardian

- [ ] Assign the organizer as the minor's guardian.
- [ ] Verify no email invitation action is offered for that minor.
- [ ] Open **Review and accept as parent/guardian**.
- [ ] Confirm the parent/guardian acknowledgement and accept.
- [ ] Verify actor=organizer guardian, target=minor, representation=`parent_or_guardian`.

## E. Minor — non-organizer guardian

- [ ] Assign another active adult participant as guardian.
- [ ] Send the invitation to that guardian's controlled test mailbox.
- [ ] Verify the organizer never sees the bearer credential.
- [ ] Accept from the guardian email and verify the minor becomes accepted.

## F. Revoke, resend, and expiry

- [ ] Send an invitation, revoke it, then open the old email; acceptance must fail generically.
- [ ] Send an invitation and select **Resend invitation**; the previous credential must stop working.
- [ ] Verify only the newest pending invitation can be accepted.
- [ ] Test an expired controlled fixture and verify it remains incomplete.
- [ ] Verify Pending, Invitation sent · Pending, Expired, Revoked, and Accepted labels are understandable.

## G. Reminder automation — controlled invocation only

- [ ] Keep Cron OFF.
- [ ] Leave one accepted booking composition-complete but one acceptance incomplete for longer than the configured 24-hour delay.
- [ ] Keep Activity reminders enabled and notification ownership active.
- [ ] Run the approved one-shot Preview reconciliation.
- [ ] Verify exactly one `customer_participant_terms_reminder` job is created for that booking/day.
- [ ] Repeat the same invocation and verify no duplicate job or inbox item appears.
- [ ] Verify the notification copy contains no participant names, email, booking UUID, code, payment, or itinerary data.
- [ ] Verify a pending, expired, or revoked invitation still leaves the participant incomplete.
- [ ] Complete the missing acceptance and verify queued work is cancelled/suppressed.
- [ ] Invoke reconciliation again and verify no new reminder is created.
- [ ] Verify no participant email invitation is automatically generated by a reminder.

## H. Suppression and cancellation

- [ ] No published excursion Terms: no reminder is generated.
- [ ] Incomplete participant composition: no reminder is generated.
- [ ] Disable Activity reminders: queued participant-Terms reminder work stops.
- [ ] Cancel, decline, or archive a controlled incomplete booking: queued reminders stop.
- [ ] Mark the operational journey completed using the established Admin state: reminders stop.
- [ ] Confirm existing participant and acceptance evidence remains unchanged.

## I. Disconnect Personal updates

- [ ] Disconnect the controlled booking under Personal updates.
- [ ] Verify future reminders stop and a due stale job cannot send.
- [ ] Verify previous Terms acceptance remains visible and immutable.
- [ ] Verify disconnect does not revoke or delete participant invitation/evidence records.

## J. Admin observability

- [ ] Open Admin → Install & Notifications → Operational automations.
- [ ] Verify **Participant Terms completion** appears as an enable/disable-only rule.
- [ ] Verify recent jobs show category, status, scheduled time and a safe failure reason when applicable.
- [ ] Verify created, deduped, sent, suppressed, cancelled and failed outcomes are diagnosable without PII.
- [ ] Verify no token, full invitation address, device credential, delivery secret, or Supabase key appears.

## K. Mobile and accessibility

- [ ] Test a narrow mobile viewport and an actual phone where available.
- [ ] Verify no horizontal scrolling or clipped warning banner.
- [ ] Verify participant cards, long names and masked email hints wrap.
- [ ] Verify invitation and guardian actions stack and remain tappable.
- [ ] Navigate controls using the keyboard and verify visible focus.
- [ ] Verify errors use alerts, status changes are announced, and meaning does not rely on color alone.
- [ ] Verify Terms text and the explicit acknowledgement remain readable at 200% zoom.

## L. Existing-function smoke checks

- [ ] Homepage and Fast Request.
- [ ] Public and Admin PWA/install routes.
- [ ] Public notification enrollment and inbox.
- [ ] Admin authentication and request list.
- [ ] Customer booking notifications.
- [ ] Reviews, booking codes, Gift Cards, Finance, analytics and Admin notifications.
