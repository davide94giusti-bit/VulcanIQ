## Configuration and compatible release

- Required server-only `SUBMISSION_HASH_SALT`: independent random secret, at least32 characters. Never reuse backend key. Trusted actor uses Cloudflare request.cf + CF-Connecting-IP; spoofed forwarded headers without platform context share a conservative unknown-actor budget. Shared networks may hit a common limit; no client-selected token bypass is added.
- Optional challenge: `TURNSTILE_SECRET_KEY`, `TURNSTILE_ENFORCE` (off), `TURNSTILE_EXPECTED_ACTION` (default public_submission). Public build variable `VITE_TURNSTILE_SITE_KEY` is not a secret. Widget action remains public_submission; change both sides together if ever renamed. Obtain a fresh token after every attempted submission; tokens are not persisted. [Official widget contract](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/) documents single-use300s tokens and expiry/error callbacks.
- Gated `ADMIN_STEP_UP_ENFORCE` and `CSP_ENFORCE`: off until owner MFA recovery and browser compatibility gates pass.
- New130000 migration is additive, service-only, no financial history changes. Historical delivery logs become dedupe fences; unresolved old rows become unknown and cannot replay. Install it with compatible Edge handlers, not after activating senders. Public mutation grant transition must ship with the new Pages/client endpoints. Existing old clients require reload/minimum-version coordination.
- No credential values are printed/stored in docs. Resend idempotency window is24h per [official provider documentation](https://resend.com/changelog/idempotency-keys); durable application acceptance/unknown state does not expire on that window. [GitHub artifact retention](https://docs.github.com/en/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization) applies independently of custom pruning.
